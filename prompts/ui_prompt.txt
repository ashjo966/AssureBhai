### Processing & Backend Pipeline Handshake
1. When "Analyze Document" is clicked:
   - Read the resolved postal data from `resolvePincode(pincode)`[cite: 14].
   - Cache `mospi_stats` in UI state for the subsequent analysis phase[cite: 14].
   - Construct `<USER_CONTEXT>` payload containing ONLY demographic and geographic fields[cite: 14]:
     `{ "primary_residence_pincode": number, "state": string, "city_tier": string, "expected_insurance_zone": string, "covered_member_age": number, "dependents": [{ "relation": string, "age": number }] }`[cite: 14].
   - Send the PDF buffer and user context via FormData to `/api/parse`[cite: 14].
   - Text extraction runs via Python (`scripts/convert_to_md.py`) and streams to Gemini 3.5 Flash Lite with JSON mode (`Health_json_template_2.json` / `Life_json_template_2.json`)[cite: 14].

2. Parser Response Handling:
   - If `document_validity.is_insurance_document === false`:
     * Display an inline warning banner on the Homepage showing `document_validity.unsupported_document_reason`[cite: 14].
     * Retain all user inputs and uploaded file state[cite: 14].
   - If `document_validity.is_insurance_document === true`:
     * Preserve the parsed policy JSON in state and display the **Disclaimer Pop-up**[cite: 14].
